1 · Entender o problema

Antes de qualquer algoritmo: o que a cidade é, e o que a prefeitura faz.

Vocabulário

cruzamento = vértice = 1..n rua = aresta = linha "A B T" T=1 mão única A→B T=2 mão dupla A↔B n = nº de cruzamentos m = nº de ruas
mão única mão dupla fechada destaque
Regra central: fechar a rua apaga só a ligação. Os cruzamentos 1 e 2 continuam no mapa. Outras ruas que tocam neles permanecem.
Q1. Depois de fechar a rua 1 (1→2), quem ainda alcança quem no exemplo acima?
Sobram: 2⇄3, 3⇄4, 4→1.
· De 2: 2→3→4→1 (todos).
· De 3: 3→2, 3→4→1 (todos).
· De 4: 4→1, 4→3→2 (todos).
· De 1: ninguém — só chega rua, não sai.
Logo não é “todo mundo alcança todo mundo”. Ainda assim há caminho ignorando a mão entre todos.
Q2. O que o decreto real exige de verdade? (trabalho ↔ casa)
Ir e voltar. Para todo par (u,v) precisa existir caminho u→v (sentido das ruas). Isso é conectividade forte (strongly connected) — não basta “haver rua ligando”.

2 · Estratégia — as 4 respostas

O juiz não quer caminho: quer um rótulo. A ordem dos testes é o raciocínio, não decoração.

-não mexer em nada
1só inverter mão única
2precisa virar mão dupla
*impossível

Por que esta ordem?

1º · Já está ok? Se com as ruas como estão (fora a fechada) todo mundo alcança todo mundo → -. Não tem que propor nada.

2º · Dá para consertar de jeito nenhum? Se nem ligando tudo em mão dupla os cruzamentos se conectam → *.

3º · Conserta só invertendo? Se existe alguma escolha de inversões de mão única que fecha o grafo → 1.

4º · Senão, precisa converter para mão dupla → 2.

Armadilha clássica: “é mão única → logo deve virar mão dupla”. Isso é falso. O exemplo 4 tem mão única e a resposta é 1 (basta inverter). O critério é estrutural, não o tipo da rua isolado.
Q3. Se o grafo sem olhar a mão já está desconectado, por que “converter tudo” não resolve?
Converter/inverter muda a direção de ruas que já existem. Não cria rua nova entre blocos separados. Se não há aresta ligando A e B, nenhum ajuste de mão inventa essa ligação.

// alcançabilidade — marcar ao processar
void dfs(int origem, vector<vector<int>>& ruas, vector<int>& vis) {
    stack<int> pilha;
    pilha.push(origem);
    while (!pilha.empty()) {
        int u = pilha.top(); pilha.pop();
        if (vis[u]) continue;
        vis[u] = 1;
        for (int v : ruas[u])
            if (!vis[v]) pilha.push(v);
    }
}
Q4. Por que if (vis[u]) continue; existe?
O mesmo vértice pode ser empilhado várias vezes (um vizinho de vários). O continue evita reprocessar e evitar laço de trabalho. Marcar ao processar (e não só ao empilhar) fica simples com essa guarda.

4 · Grafo reverso

Dois DFS a partir de 1: um no grafo, um no espelho.

Como montar o espelho

Rua originalEm ruasEm ruas_inverso
T=2 mão dupla a—ba→b e b→aa→b e b→a (igual)
T=1 mão única a→bsó a→bsó b→a
Por quê funciona: se 1 alcança todos e todos alcançam 1 (segundo DFS = “todos alcançam 1”), então para quaisquer u,v: u→…→1→…→v. Fortemente conexo.
Q5. O espelho é “a cidade com ruas invertidas como solução”?
Não. O espelho é ferramenta de verificação do estado atual. Inverter ruas como solução é outra pergunta (existencial) — casos 1 e 2.

5 · Por que olhar sem direção

Detectar *: impossibilidade absoluta.

com mão
ignorando a mão

Exemplo mínimo do *:

4 2
1 2 2    ← fechada
3 4 2    ← sobra só isto

Sobram dois blocos: {1,2} e {3,4}. Não há rua entre eles. Converter mão não cria rua nova → *.

Q6. E se houver rua, mas só de mão única ligando os blocos — ainda é *?
Não. Se existe rua (em qualquer sentido), dá para inverter e/ou torná-la mão dupla. * só quando o grafo sem mão está desconectado.

6 · Pontes

Rua de corte: sem ela, a cidade (sem olhar a mão) parte em dois.

Definição operacional

Aresta e = (u,v) é ponte se remover e aumenta o número de componentes conexas do grafo não direcionado.

No código a gente não apaga de verdade: usa tin/low.

Q7. No caminho 2—3—1, quantas pontes existem? Por quê?
Duas: 2—3 e 3—1. Cada uma é a única ligação de um lado. Tirar 2—3 isola 2; tirar 3—1 isola 1.

7 · tin e low

Relógio da DFS + “o mais alto que a subárvore consegue voltar”.

VérticetinlowSignificado
Arestas da árvore: setas verdes · retorno: laranja · ponte: vermelha tracejada

Condição de ponte

Para aresta de árvore u → v (u descobriu v):

low[v] > tin[u]   ⇒  (u,v) é PONTE
RelaçãoSignificado
low[v] > tin[u]subárvore de v não volta a u nem acima → ponte
low[v] == tin[u]v alcança u por retorno → não é ponte
low[v] < tin[u]v alcança ancestral de u → não é ponte
Não misturar: isto é ponte em grafo não direcionado. Tarjan de componentes fortemente conexas é outro assunto (outro uso de low).

8 · Por que o tipo da rua importa

Achar a ponte não basta: precisamos saber se ela nasceu mão única.

Ponte é…Inverter resolve?Rótulo
mão dupla (já vale 2 sentidos)o gargalo não é elase alguma ponte for mão única → 2
mão única (só 1 sentido em qualquer orientação)não — precisa converter
não existe ponte mão únicasim, dá para orientar o resto1
Resumo de decisão após - e * descartados:
existe ponte de mão única? → 2 · senão → 1
Q8. Por que ponte mão única não pode ser resolvida só com inversão?
Inverter troca o sentido, mas a rua continua de um sentido só. Como é a única ligação entre duas partes, um lado nunca alcança o outro. Só convertendo para mão dupla os dois sentidos passam a existir.

Por que id da aresta e não só o pai?

Se existem duas ruas entre o mesmo par (multi-aresta), identificar só pelo vértice pai pode errar: a segunda rua vira “retorno” e não é ponte. Cada rua precisa de id próprio.

Função de pontes

void dfs_pontes(int u, int aresta_pai, ...) {
    vis[u] = 1;
    tin[u] = low[u] = timer_dfs++;
    for (auto [v, id] : adj[u]) {
        if (id == aresta_pai) continue;
        if (vis[v]) low[u] = min(low[u], tin[v]);   // retorno
        else {
            dfs_pontes(v, id, ...);
            low[u] = min(low[u], low[v]);
            if (low[v] > tin[u]) {          // PONTE
                if (mao_unica[id]) tem_ponte_mao_unica = true;
            }
        }
    }
}
